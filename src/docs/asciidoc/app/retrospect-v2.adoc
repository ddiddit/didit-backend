== 회고 V2

회고 V2는 고정 질문 순서 없이 사용자의 업무 경험을 바탕으로 AI가 후속 질문 하나를 생성합니다.

=== 대화형 회고

첫 안내 메시지만 `title`과 `body`를 사용하고, 이후 대화 메시지는 `content`만 사용합니다.
`readyToComplete`는 결과 생성 가능 여부를 나타냅니다. 종료 메뉴와 호출 API는 `action`과 `readyToComplete`를 함께 보고 결정합니다.

==== 대화 액션

메시지 전송 응답의 `data.action`과 대화 조회 응답의 `data.turns[].action`은 AI 응답 이후 클라이언트가 처리할 동작을 나타냅니다.

[cols="1,3",options="header"]
|===
|값 |클라이언트 처리
|`ASK` |AI 질문을 표시하고 사용자 입력을 계속 받습니다.
|`REFLECT` |질문 없는 AI 반응을 표시하고 사용자 입력을 계속 받습니다.
|`OFFER_COMPLETION` |서버가 회고 종료를 제안한 상태입니다. 아래 종료 메뉴 계약에 따라 처리하고, 계속하기를 선택하면 `conversationIntent=CONTINUE_AFTER_COMPLETION`으로 메시지를 전송합니다.
|`CONFIRM_COMPLETION` |사용자가 `더 할 말 없어`, `그만할게`, `끝내자`처럼 회고 전체를 마치려는 의사를 명확히 표현했거나, 결과 생성이 어려운 상태에서 항목 답변을 3회 연속 건너뛰었거나 질문 후보가 소진된 상태입니다. `없어`, `없는 것 같아` 한 번만으로는 반환하지 않습니다.
|===

첨부파일을 비동기로 분석하는 동안 메시지 전송 응답의 `action`은 `null`입니다. 분석 완료 후 대화 조회 응답에서 해당 턴의 `action`을 확인합니다.
`readyToComplete`가 `false`여도 질문 횟수 기준에 따라 `OFFER_COMPLETION`이 반환될 수 있습니다. 따라서 종료 메뉴 노출은 `action`으로, 메뉴 문구와 종료 API는 `readyToComplete`로 결정합니다.

==== 답변 예시

AI 메시지의 `answerGuide`는 답변 예시를 제공할 때만 반환되며, 기존 클라이언트는 이 필드를 사용하지 않아도 대화를 계속할 수 있습니다.

[cols="1,3",options="header"]
|===
|`mode` |클라이언트 처리
|`INLINE` |질문과 함께 `examples`를 바로 표시합니다. 현재는 다음 행동 질문에 사용합니다.
|`ON_DEMAND` |`답변 예시 보기`와 같은 선택 UI를 표시하고, 사용자가 요청했을 때 `examples`를 펼칩니다.
|===

`examples`는 현재 회고 맥락에 맞는 2~3개의 한 문장 예시입니다.
사용자가 예시를 선택하면 선택한 문구를 새로운 `clientMessageId`의 일반 `TEXT` 메시지로 전송합니다. 별도 intent나 API는 사용하지 않습니다.
예시를 화면에 표시한 것만으로는 회고 결과의 근거가 되지 않으며, 사용자가 선택하거나 직접 입력해 전송한 메시지만 일반 검증을 거쳐 반영됩니다.
동일 메시지 재전송과 대화 조회에서도 저장된 `answerGuide`가 동일하게 반환됩니다.

==== 메시지 전송

동일한 `clientMessageId` 와 내용으로 재전송하면 이미 완료된 응답을 반환합니다.
`inputType` 은 `TEXT` 또는 `STT`이며 생략하면 `TEXT`로 저장됩니다. STT 변환 텍스트를 사용자가 수정한 뒤 전송할 때는 `STT`를 전달합니다.
`attachmentIds`에는 업로드 완료된 파일 ID를 최대 3개까지 전달할 수 있으며, 첨부파일이 있으면 `content`는 비어 있어도 됩니다.
`conversationIntent`를 생략하면 `NORMAL`로 처리합니다. `OFFER_COMPLETION`에서 사용자가 계속하기를 선택한 경우에만 사용자 선택 문구와 함께 `CONTINUE_AFTER_COMPLETION`을 전달합니다.
`CONTINUE_AFTER_COMPLETION`은 `TEXT` 입력으로만 사용할 수 있으며 첨부파일과 함께 보낼 수 없습니다. 서버는 종료 제안을 반복하지 않고 질문 가능한 다른 회고 항목을 이어서 질문합니다.
계속하기 선택은 이전 메시지의 `clientMessageId`를 재사용하지 않고 새로운 ID로 전송합니다.

첨부파일이 있는 메시지는 파일 분석을 비동기로 시작하고 `assistantMessage`를 `null`로 반환합니다.
클라이언트는 대화 조회 API를 호출해 해당 턴이 `PROCESSING`에서 `COMPLETED` 또는 `FAILED`로 바뀌는지 확인합니다.
읽을 수 없는 파일은 재시도 실패로 남기지 않고 안내 메시지와 함께 턴을 `COMPLETED`로 종료합니다.
분석된 텍스트에서 개인정보 또는 인증정보가 감지되면 서버가 AI 응답 앞에 삭제 권고 문구를 추가하며, 감지된 원문 값은 응답에서 반복하지 않습니다.

==== 대화 종료 선택 계약

상단 `회고 마치기`에서 `readyToComplete=false`이면 기존 2단계 경고를 사용합니다. 첫 번째 시도에는 `아직 내용이 충분하지 않아요.` 안내와 `확인`을 표시하고, 두 번째 시도에는 `아직 회고 결과 생성이 어려워요.` 안내와 `계속하기`, `나가기`를 표시합니다. `나가기`는 아래 결과 없는 종료 API를 호출합니다.

대화 응답의 `action`이 `OFFER_COMPLETION` 또는 `CONFIRM_COMPLETION`이면 다음 계약을 사용하며 상단 버튼의 2단계 경고 상태와 공유하지 않습니다.

* `readyToComplete=true`: `계속 작성하기`, `이대로 마치기`를 표시합니다. 사용자가 명시적으로 종료한 `CONFIRM_COMPLETION` 응답은 `assistantMessage=null`일 수 있습니다. `이대로 마치기`는 결과 생성 API(`/finish`)를 호출합니다.
* `readyToComplete=false`: AI 안내에 결과 미생성과 이용 횟수 1회 차감 내용이 포함됩니다. `계속 작성하기`, `이대로 마치기`를 표시하고, `이대로 마치기`는 추가 확인 없이 결과 없는 종료 API(`/exit`)를 호출합니다.

`계속 작성하기`는 현재 대화를 유지합니다. `OFFER_COMPLETION`에서 계속 작성하기를 선택한 경우에만 새 메시지와 `conversationIntent=CONTINUE_AFTER_COMPLETION`을 전송합니다.
상단 종료 경고 상태는 새 메시지 제출, `CONTINUE_AFTER_COMPLETION` 전송, 화면 재진입, `readyToComplete=true` 전환 시 초기화합니다.
두 API를 호출하는 동안 종료 버튼과 메시지 입력을 비활성화하고, 실패하면 현재 화면과 선택창을 유지해 재시도할 수 있게 합니다.

==== 대화 종료 및 결과 생성

`readyToComplete=true`인 대화만 확인된 내용을 바탕으로 구조화 회고 결과를 생성하고 저장합니다.
내용이 부족한 상태에서 직접 호출하면 `409 Conflict`가 반환되므로, 클라이언트의 `readyToComplete`는 화면 힌트이고 서버가 최종 준비도를 다시 검증합니다.

완료된 회고에 같은 요청을 다시 보내면 저장된 결과를 반환하며, 생성 실패 시에는 다시 시도할 수 있도록 생성 상태를 복구합니다.

성공 시 `resultGenerationStatus`는 `GENERATED`이며 자동 생성된 제목과 구조화 결과를 함께 반환합니다.
`summary`, `insight`, `nextActions`는 항상 존재하고 `insight`와 `nextActions`는 각각 정확히 1개입니다.
다음 행동 제목은 홈에서도 그대로 사용하는 `~하기` 형태입니다.

결과 화면은 `summary` → `strengths` → `improvements` → `processes` → `learnings` → `insight` → `nextActions` 순서로 렌더링합니다.
`strengths`, `improvements`, `processes`, `learnings`는 실제 대화에서 수집된 경우에만 응답에 포함되므로, 누락된 필드는 빈 카드나 `대화에서 확인되지 않았어요` 문구로 대체하지 않고 섹션 전체를 생략합니다.

=== 첨부파일 업로드 URL 생성

JPG, PNG, PDF, TXT, MD 파일을 지원하며 파일당 최대 10MB입니다. 업로드 요청에는 파일 본문의 SHA-256 값을 Base64로 인코딩한 `checksumSha256`을 전달합니다. 반환된 URL에 요청한 `Content-Type`, `Content-Length`, `x-amz-checksum-sha256` 헤더를 동일하게 넣어 PUT한 뒤 업로드 완료 API를 호출합니다. 체크섬이 달라지면 S3가 업로드를 거부하므로 같은 URL로 다른 파일을 덮어쓸 수 없습니다.

클라이언트는 파일 선택 전에 `회사 기밀이나 개인정보가 포함된 파일은 첨부하지 않도록 주의해 주세요.` 안내를 노출해야 합니다.
